## 📝 Commit Message Standards

### **Format**

```
Phase X.Y: Brief description (max 50 chars)

- Detailed change 1
- Detailed change 2
- Detailed change 3

Affected modules: module1, module2
Testing: Description of tests performed
FDA/MDR Impact: [None|Low|Medium|High]
```

### **Examples**

```

Affected modules: All 6 modules

FDA/MDR Impact: None (technical compatibility)
```

```
Phase 11.2: Vendor Risk Scoring System

- Added risk_score computed field to vendor.certification model
```

## 🔄 Standard Workflow (After Every Phase)

### **Step 1: Check Status**

```powershell
# Navigate to project folder
cd D:\odoo\odoo19\PROGECTS\MedTech_ERP\

# Check what files changed
git status

# Review changes before committing
git diff
```

### **Step 2: Stage Changes**

```powershell
# Stage all changes (use cautiously)
git add .

# OR stage specific files/folders
git add medtech_traceability/
git add IMPLEMENTATION_PLAN.md
```

### **Step 3: Commit with Descriptive Message**

```powershell
# Single-line commit (for small changes)
git commit -m "Phase 9.1: Traceability Dashboard OWL Component"

# Multi-line commit (recommended for features)
git commit

# This opens editor - write detailed message following format above
```

### **Step 4: Push to GitHub**

```powershell
# Push to main branch
git push origin main

# OR push to feature branch
git push origin feature/phase-11-analytics
```

### **Step 5: Verify on GitHub**

- Visit: https://github.com/sabryyoussef/edafa_MedTech
- Check commit appears in history
- Verify files updated correctly

## 📦 What to Commit (Checklist)

### ✅ **Always Commit**

- [ ] Python source files (`*.py`)
- [ ] XML view files (`*.xml`)
- [ ] JavaScript files (`*.js`)
- [ ] CSS files (`*.css`, `*.scss`)
- [ ] Manifest files (`__manifest__.py`)
- [ ] Security CSV files (`ir.model.access.csv`)
- [ ] Documentation files (`*.md`)
- [ ] Configuration templates (without credentials)
- [ ] Demo data (`demo/*.xml`)

### ❌ **Never Commit**

- [ ] Python cache (`__pycache__/`, `*.pyc`)
- [ ] Log files (`*.log`, `logs/`)
- [ ] Database files (`*.sql`, `*.db`)
- [ ] Credentials (`odoo.conf` with passwords)
- [ ] IDE settings (`.vscode/`, `.idea/`)
- [ ] Temporary files (`*.tmp`, `*.bak`)
- [ ] OS files (`.DS_Store`, `Thumbs.db`)

## 🚀 Quick Commands Reference

### **Daily Operations**

```powershell
# Start of day - get latest changes
git pull origin main

# After completing a phase/feature
git add .
git commit -m "Phase X.Y: Description"
git push origin main

# Check commit history
git log --oneline -10

# Undo last commit (keep changes)
git reset --soft HEAD~1

# Discard all uncommitted changes (DANGER!)
git reset --hard HEAD
```

### **Working with Branches**

```powershell
# Create new feature branch
git checkout -b feature/phase-12-atp-logic

# Switch to main branch
git checkout main

# Merge feature into main
git checkout main
git merge feature/phase-12-atp-logic

# Delete branch after merge
git branch -d feature/phase-12-atp-logic
```

### **Emergency Rollback**

```powershell
# Revert specific commit
git revert <commit-hash>

# Reset to specific commit (DANGER - rewrites history)
git reset --hard <commit-hash>

# Create backup branch before dangerous operations
git branch backup-$(Get-Date -Format "yyyyMMdd-HHmm")
```

## 📊 Compliance Considerations

### **FDA 21 CFR Part 11 (Electronic Records)**

Git commits serve as **audit trail** for code changes:

- **Who**: Git author (configured user.name)
- **What**: Specific code changes (diff)
- **When**: Commit timestamp
- **Why**: Commit message justification

### **Traceability Requirements**

Link commits to:
- Implementation plan phases
- CAPA records (if fixing bugs from production)
- Regulatory requirements (FDA, MDR, ISO references)

```
Phase 11.3: Risk Management Library

Implements ISO 14971:2019 risk management requirements

FDA Reference: 21 CFR 820.30(g) - Risk analysis

- Created medtech.risk.assessment model
- Added severity/probability matrix (1-5 scale)
...
```

## 🆘 Troubleshooting

### **Problem: Accidentally committed sensitive data**

```powershell
# Remove file from Git but keep locally
git rm --cached sensitive_file.conf

# Add to .gitignore
echo "sensitive_file.conf" >> .gitignore

# Commit the removal
git commit -m "Security: Remove sensitive configuration file"
git push origin main
```

### **Problem: Merge conflicts**

```powershell
# Pull latest changes
git pull origin main

# Conflicts appear in files - edit manually
# Look for <<<<<<< HEAD markers

# After resolving
git add .
git commit -m "Merge: Resolved conflicts in module_name"
git push origin main
```

### **Problem: Need to undo push to GitHub**

```powershell
# Revert specific commit (creates new commit)
git revert <commit-hash>
git push origin main

# Force push (DANGER - only for personal repos)
git reset --hard <previous-commit>
git push --force origin main
```
